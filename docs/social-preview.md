# Общий сад и голос — preview для ревью

Рома подтвердил 14.11.2026: показ дерева добровольный, голос только по кнопке. Главный критерий готовности — не затронуть живые данные. Эта ветка не публикуется на рабочий сайт и не применяет миграции в production.

## Минимальный вариант

- Используется существующий экран общего сада. Демонстрационных деревьев в приложении нет. В тестах имена синтетические и явно тестовые.
- Для каждого имени игрок отдельно выбирает «Показывать моё дерево». Перед кнопкой видны имя для публикации и состав публичных данных. Отозвать согласие можно той же кнопкой. Дополнительная старая настройка скрытия также действует.
- Новая таблица согласий не заполняется из старого hidden=false или ng_save. Ни старые, ни новые строки без отдельного согласия не возвращаются даже старым RPC ng_public. Обычное сохранение игры не меняет согласие. Публичный ответ содержит только id дерева, псевдоним, вид и урожай (apples/flowers/waters/mon/monKey); история, активность, ключ/хеш игрока, email и закрытая статистика не передаются.
- До установки серверной части экран закрыт, не читает старый общий список и не предлагает публикацию. Старые автоматические записи public trees через адаптер Claude в этой ветке отключены. Ранее опубликованные старым приложением данные этим PR автоматически не удаляются.
- Подбадривание — один короткий уважительный текст, не сообщение от реального участника. Текст всегда виден. Отдельные кнопки «Прослушать» и «Остановить», сохраняемое отключение, остановка при уходе с экрана/смене имени. Нет автозвука, микрофона или записи голоса.
- Используется только локальный браузерный голос с подходящим языком и localService=true. Если голоса нет/он ещё не загружен, остаётся текст; voiceschanged обновляет доступность. Ошибка озвучивания тоже оставляет текст. Это не обещание наличия RU/EN/HE голоса на устройстве. См. [SpeechSynthesisVoice.localService](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisVoice/localService).
- RU/EN/HE и RTL поддержаны через существующий генератор i18n. На страницах явная маркировка preview; версия исходной базы3.5 не выдаётся за новый production-релиз.

## Изоляция и воспроизведение

В preview HTML SB_URL и SB_KEY намеренно пусты: простое открытие ветки не подключается к рабочей Supabase. Не подставлять production-конфигурацию для проверки. В репозитории нет подтверждённой отдельной удалённой тестовой Supabase или бэкапов production; они этим PR не создавались.

Существующий локальный стенд PGlite создаёт базу в памяти, роли, синтетических игроков и имитацию Data API/Auth. Он не соединяется с Supabase. Стенд подменяет конфигурацию HTML на127.0.0.1 и локальный ключ; ожидает ровно одну замену. Проверяет свободные тестовые порты, слушает только loopback. В браузерных тестах все non-loopback запросы блокируются, service workers отключены; отдельный тест доказывает отказ запросу к внешнему адресу. Пользовательский профиль Chrome не используется.

Требуется Python3.12+ для существующего i18n/build.py, Node и зависимости для локального тестирования:

```sh
npm install --no-save --package-lock=false @electric-sql/pglite
python3 -m venv /tmp/ng-preview-venv
/tmp/ng-preview-venv/bin/pip install playwright
/tmp/ng-preview-venv/bin/playwright install chromium
python3 i18n/build.py
node tests/db-test.mjs supabase.sql 0 --selftest
/tmp/ng-preview-venv/bin/python tests/social-test.py
NG_SOCIAL=0 NG_SCHEMA=3 /tmp/ng-preview-venv/bin/python tests/social-test.py
NG_SCHEMA=3 /tmp/ng-preview-venv/bin/python tests/browser-test.py
```

Новая миграция — supabase-social.sql, отдельная от ранее применённых схем. Она совместима со схемами2/3 и подготовленной4, повторяема, не переписывает строки игроков. Проверяется только на локальном стенде; запуск production не разрешён этим PR. Для ручного просмотра можно запустить `/tmp/ng-preview-venv/bin/python tests/social-preview.py`: он создаёт только две явно тестовые записи в локальной памяти, печатает localhost-ссылки; Ctrl+C останавливает стенд. Переключатели языка относительные и остаются в preview.

Для будущей проверки на удалённом стенде нужна отдельная тестовая Supabase с синтетическими данными. Перед рабочим выпуском отдельно требуются подтверждение бэкапов, ревью миграции, выбор одного исполнителя и решение о релизе; старые схемы2/3 повторно не запускать.

## Результаты и границы ревью

Локальные результаты 14.11.2026: база145/145; целевой браузерный набор26/26; без новой миграции20/20; существующий регрессионный набор на NG_SCHEMA=3 —94/94. В последнем целевом прогоне дополнительно проверены локальные/удалённые голоса и старый адаптер Claude. Независимый Codex-помощник выявил два риска (legacy-публикация и production-конфигурация preview); оба исправлены и покрыты проверками. Результаты также приведены в PR. Голосовые контролы проверяются с подставленным SpeechSynthesis, без звука: это не проверка слышимости, качества/произношения или доступности голоса в реальном устройстве. Реальные Google-вход, владелец и production-прогресс не проверяются и не меняются. Нужна ручная проверка звука на целевых устройствах, в том числе устройствах без локального Hebrew-голоса.

Независимое ревью внутри Codex не является ревью Claude. Реальному Claude отведены только код и тесты, без деплоя; этот PR подготовлен для передачи ему по ссылке вручную. Связь с Claude/Grok не устанавливалась, платные API не вызывались. Общий контекст команды пока находится в отдельном документационном draft PR.
