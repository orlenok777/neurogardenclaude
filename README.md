# НейроСад 2.0 — NeuroGarden Claude (прототип)

Текущая версия сайта: **3.1**. Схема базы: **2**.

Страницы: [русская](https://orlenok777.github.io/neurogardenclaude/), [иврит](https://orlenok777.github.io/neurogardenclaude/he.html), [английская](https://orlenok777.github.io/neurogardenclaude/en.html).

Одностраничное приложение: `index.html`, без сборки и зависимостей.

## Что внутри

- 26 игр на память, внимание, логику и пространственное мышление, по 5 уровней.
- Личное дерево: красное яблоко за пройденный раунд, зелёное за результат ниже 60%, надкусанное за недоигранную игру.
- Игра под именем без регистрации; на одном устройстве можно завести несколько имён.
- Календарь занятий, награды, полив, птица, «Добрые слова», пробный раунд, звуки, минутка дыхания.
- Панель администратора: деревья и прогресс каждого участника, ободрение участнику, вкладка «Максимальная статистика».
- Озвучка заданий, крупный текст, отключение анимации, тёмная тема.

## Важно про хранение данных

Страница написана для запуска как артефакт Claude. Аккаунты, общий сад, панель администратора,
«Добрые слова» и голос Claude работают через среду Claude (`window.claude`: `db`, `user`, `room`, `tts`).

Если открыть `index.html` где-то ещё (например, на GitHub Pages), работают все игры и личный сад
в режимах «На этом устройстве» и «Без сохранения». Общего сада и панели администратора там нет:
для них нужен собственный сервер с авторизацией и базой данных (например, Supabase).

Результат раунда считает браузер игрока, серверной проверки нет.

Практика внимания и памяти · Не диагностика и не лечение.

## Игра для всех без регистрации (Supabase)

Чтобы любой посетитель сайта мог написать имя и играть, а администратор видел всех участников,
сайту нужна своя база данных. Здесь используется бесплатный проект Supabase.

1. Создайте проект на https://supabase.com.
2. Откройте SQL Editor, вставьте содержимое файла `supabase.sql` и нажмите Run.
3. Задайте пароль администратора отдельным запросом (пароль придумайте свой):

   ```sql
   insert into public.ng_config (k, v)
   values ('admin', extensions.crypt('ВАШ_ПАРОЛЬ', extensions.gen_salt('bf')))
   on conflict (k) do update set v = excluded.v;
   ```

4. В `index.html` впишите адрес проекта и публичный ключ (publishable key) в строку
   `const SB_URL='', SB_KEY='';`.
5. Включите GitHub Pages для ветки `main`.

Как это работает:

- Игрок опознаётся случайным ключом в его браузере, без почты и пароля. Дерево привязано к этому браузеру.
- Таблицы закрыты от прямого доступа, сайт работает только через функции из `supabase.sql`.
- Панель администратора открывается по паролю; в базе хранится только его хеш.
- Панель обновляется опросом базы раз в 12 секунд, игрок считается онлайн, если был на связи в последние 75 секунд.
- После 5 неверных паролей администратора с одного адреса вход с этого адреса закрывается на 15 минут.
- Если одно имя открыто в двух вкладках, раунды из обеих сохраняются: сервер замечает устаревшее сохранение, сайт объединяет историю.
- Удалённое имя не возвращается поздним сохранением из другой вкладки.
- Всё, что приходит из базы, сайт пересобирает по полям перед показом: чужая запись не может вставить разметку в панель.
- Публичный ключ виден всем посетителям, это нормально. Секретный ключ (secret key) в сайт вписывать нельзя.

## Языки и версии

- `index.html` — русская страница и одновременно исходник. `he.html` и `en.html` собираются из неё и вручную не правятся.
- `i18n/en.json` и `i18n/he.json` — переводы каждого русского фрагмента. Если в исходнике появился новый русский текст
  без перевода, сборка останавливается и называет его.
- `releases.json` — список релизов: номер, дата коммита, хеш. Блок версий вверху каждой страницы строится из двух
  последних записей и показывает время Израиля. Хеш текущего релиза дописывается при следующем релизе: коммит не может содержать собственный хеш.
- Адрес и публичный ключ Supabase записаны в `index.html` один раз и попадают во все три страницы при сборке.

## Чеклист публикации

1. Внести правки в `index.html`. Новые русские тексты перевести в `i18n/en.json` и `i18n/he.json`.
2. Добавить в `releases.json` новую запись: номер на 0.1 больше прежнего, время в поясе Asia/Jerusalem.
   В предыдущую запись вписать хеш её коммита.
3. Выполнить `python3 i18n/build.py`.
4. Проверить синтаксис скриптов трёх страниц и запустить оба набора тестов (база и браузер).
5. Открыть все три страницы на ширине телефона: вверху виден новый номер версии с датой, ниже предыдущая версия.
6. Сделать коммит с датой из `releases.json` и отправить ветку.
7. Опубликовать русскую страницу в Claude с тем же номером версии (поля Supabase там пустые).
8. Если менялся `supabase.sql`, увеличить номер схемы и применить файл к базе одним исполнителем.

## Тесты базы

`tests/db-test.mjs` поднимает Postgres внутри Node (пакет `@electric-sql/pglite`), применяет `supabase.sql` дважды
и выполняет все вызовы от имени роли `anon`:

```
npm install @electric-sql/pglite
node tests/db-test.mjs supabase.sql 0 --selftest
```

Проверяется: закрытость таблиц и внутренних функций для `anon`, изоляция между ключами, проверка входных данных,
версии сохранения, запрет воскрешения удалённых имён, границы администратора и блокировка после неверных паролей.
Это не настоящая Supabase: заголовки запроса, Data API и ключи проекта так не проверяются.

## Тесты в браузере

`tests/browser-test.py` раздаёт три собранные страницы с одного адреса, как GitHub Pages, подменяет адрес базы
на локальный стенд из `tests/db-test.mjs` и управляет Chromium:

```
npm install @electric-sql/pglite
pip install playwright && playwright install chromium
python3 tests/browser-test.py
```

Проверяется: одно имя в одной вкладке с перезагрузкой; русская вкладка играет раунд, а английская или ивритская
открыта и сохраняет в это время; два раунда одновременно в двух вкладках; брошенный раунд; подхват чужого результата
при возврате во вкладку; изоляция двух браузеров и двух имён; режим «На этом устройстве» в двух вкладках; блок версий.
Настоящая база и настоящий сайт этим набором не затрагиваются.

## Несколько вкладок

- Раунд в процессе помечен вкладкой, которая его начала. Другая вкладка его не трогает, пока ему меньше 30 минут.
- Если вкладку с раундом закрыли, раунд станет «не доигран» при старте следующего раунда или через 30 минут.
- При расхождении сохранений история объединяется; для одного и того же раунда завершённая запись всегда
  заменяет запись «не доигран».
